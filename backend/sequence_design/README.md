# PepperQ sequence design (new workflow, contract 1.0)

**Large-circuit addition:** opt-in analytical construction and bounded MPS
simulation/circuit preparation now support up to **50 variable positions**.
See [LARGE_CIRCUITS.md](LARGE_CIRCUITS.md) for objective restrictions, approximation,
honest timing comparisons and reproduction. The documentation below describes
the preserved small exact mode, whose limit remains eight variable positions.

This module designs **one sequence** by choosing amino acids at positions.
It does not select a blend. The old library, blend designer/optimizer, molecular
analysis, and HeH+ VQE pages and APIs remain accessible and unchanged in meaning.
Open **Sequence Design** at `/sequence-design` in the frontend navigation.

## What is implemented

- Redesign an existing standard sequence or design from an explicit length.
- 2-50 total residues, including fixed positions. At most **eight variable
  positions**, exactly two distinct choices at each variable position. This is
  the implementation's validated bound, not an agreed QPU hardware limit.
- Global allowed and excluded sets; explicit fixed/variable choices at positions.
  Exclusions override the allowed set. Allowed residues need not all appear.
- Required amino acids must each appear at least once in the completed sequence.
- Optional maximum Hamming-distance mutation count relative to a template.
- Estimated charge at a specified surrounding pH and a desired GRAVY range.
- An optional adjacent-identical-residue preference, explicitly a pattern-design
  choice, not a prediction of physical interactions or stability.
- Real Qiskit QAOA simulation, actual optimization history and simulated shots,
  feasible candidate sequences, exact classical benchmark, gap and probability.
- Explicit no-feasible-sample behavior, tied optima, source assumptions, circuit
  text, Composer-compatible QASM, complete JSON export, and molecular connectivity.
- A 2D connectivity SVG generated by RDKit, not an electronic-structure result,
  a 3D conformer, or a folding prediction. The existing 3D viewer remains on the
  Molecular Analysis page.

The default input is the illustrative standard-residue template `GAGAGAGA`, with
A/K choices at positions 2,4,6,8, at least one K required and at most two changes.
It is an input example, not a therapeutic reference or experimentally validated
design. Applying a different template resets all positions to fixed, explicitly
requiring the researcher to choose editable positions.

## Honest quantum interpretation

The restricted sequence problem has a valid diagonal cost Hamiltonian. It is
appropriate for a QAOA implementation and a controlled hackathon experiment.
**It is not evidence that quantum computing improves peptide design or beats
classical optimization.** Charge and GRAVY are classical, composition-dominated
descriptors; multiple residue orderings can tie. Local terminal-residue charge
conventions can also distinguish terminal choices. Only the optional repeat term
explicitly imposes a local ordering preference. No folding, binding, reaction,
efficacy or laboratory result is inferred.

For this small prototype the complete allowed space is enumerated classically
to construct/verify the cost and exact reference. It is not a scalable oracle
or a demonstration of quantum advantage. The QAOA optimizer minimizes the
expectation of a cost encoded in a circuit, while the reported proposal is the
lowest-cost **feasible sequence actually observed in its simulated shots**.
Never substitute the exact classical answer as a quantum proposal.

## Cost, constraints, and mathematical representation

Read-only reuse of `backend.peptide_analysis.analyze_sequence` supplies estimated
net charge q at researcher-specified pH, mean Kyte-Doolittle GRAVY h, average
molecular mass, and estimated pI. Biopython's Bjellqvist pKa model and free-terminal,
linear, unmodified-chain assumptions are retained. pH describes the solution;
pI is reported separately and is not the optimization target.

For weights wq, wh, wr (nonnegative, positive total), minimize the raw objective:

```
d_h = max(h_min - h, 0, h - h_max)
r = number of identical adjacent residue pairs / (length - 1)
raw = [wq*((q-target_charge)/2)^2 + wh*d_h^2 + wr*r] / (wq+wh+wr)
```

The fixed 2 e charge and 1 GRAVY scales are transparent research design choices,
not fitted biological constants. The nonnegative objective is not bounded by 1.
Charge and hydropathy are **soft goals**: a feasible result can still miss them.
Report the deviations rather than claiming target attainment or solubility.

Length, fixed positions, allowed/excluded residues and per-position alternatives
are enforced by the encoding. For other hard constraints:

```
violation = number_of_missing_required_residue_types
            + max(0,mutation_count-max_mutations)^2
lambda = max(raw over allowed states)-min(raw over allowed states)+1
E = raw + lambda*violation
```

Omit the mutation term if no budget is supplied. Since a violation is an integer
of at least one, lambda dominates the full raw range: every feasible penalized
state is below every infeasible state. This is checked exhaustively. Infeasible
shot outcomes can still occur and are reported, not hidden. A fully infeasible
design request fails before any QAOA execution.

Each bit i selects choice 0 or 1 at variable position i, in ascending positional
order. Position indices in the API are one-based; qubits are zero-based. The
rightmost displayed bit is qubit 0. Fixed positions consume no qubits.

A Boolean Möbius transform reconstructs the full cost polynomial and validates
all states. If degree<=2, the result includes an **upper-triangular QUBO**:
`E=constant+x.T@Q_upper@x` (pairs counted once). The existing
`backend.blends.quantum.qubo_to_ising` and `build_blend_circuit` are reused as
generic native RZ/RZZ/RX QAOA machinery; bit meanings are supplied by this module.

Required-at-least-once, squared range-distance, and budget inequalities can
produce higher-order terms. Those are **not silently truncated to a QUBO**.
Instead the exact energies become `DiagonalGate(exp(-i*gamma*scaled_E))`, followed
by RX(2 beta) mixers. It is a valid higher-order diagonal cost Hamiltonian with
`scaled_E=(E-min(E))/max(ptp(E),1e-12)`. On the quadratic path the constant offset
is omitted as an irrelevant global phase with the same scale. Primitive gate
expansion for QASM reuses the existing display/export helper without altering it.

## Backend contract

- `POST /api/v1/sequence-design/preview`: validates the design space, counts
  feasible states, reports variable mapping/cost representation/template
  descriptors; **does not execute QAOA**. Supports fully fixed sequences.
- `POST /api/v1/sequence-design/optimize`: same request, at least one variable
  position required; runs local ideal QAOA and returns verified comparison data.
- `POST /api/v1/sequence-design/structure`: `{ "sequence": "GAGA" }` returns
  sequence, trusted RDKit SVG, provenance and the 2D model description.

Example design request:

```json
{
  "length": 8,
  "template_sequence": "GAGAGAGA",
  "allowed_amino_acids": ["G", "A", "K"],
  "excluded_amino_acids": [],
  "required_amino_acids": ["K"],
  "positions": [
    {"position": 2, "choices": ["A", "K"]},
    {"position": 4, "choices": ["A", "K"]},
    {"position": 6, "choices": ["A", "K"]},
    {"position": 8, "choices": ["A", "K"]}
  ],
  "max_mutations": 2,
  "goals": {
    "ph": 7.4, "target_charge": 2, "charge_weight": 1,
    "hydropathy_min": -1.5, "hydropathy_max": 0.5,
    "hydropathy_weight": 0.5, "adjacent_repeat_weight": 0
  },
  "layers": 1, "max_iterations": 60, "shots": 2048, "seed": 42
}
```

In template mode unspecified positions are locked to the template. In length
mode (`template_sequence=null`) unspecified positions use the effective global
alphabet; more than two choices at any position fail. For long designs provide
explicit fixed-position rules and no more than eight binary variable positions.
The frontend always sends explicit choices for every position.

Response fields: UUID/time/request; variable-position mapping and domains;
best_sampled (null if none), candidate_sequences (up to ten observed feasible
sequences), classical_reference, benchmark; full state table with properties,
weighted components, raw and penalized scores, feasibility, ideal probabilities,
simulated counts and empirical frequencies; polynomial/optional QUBO/penalty;
reconstruction validation; actual history, fitted parameters and convergence;
native circuit text, expanded OpenQASM 2 and gate metadata; methods/limitations.

Simulator execution is explicit. No IBM credentials, hardware submission or QPU
usage is involved. Hardware integration would need job handling and measured
counts kept distinct from ideal statevector probabilities.

## Run and verify

From the project root with the environment active:

```powershell
python -m uvicorn backend.api:app --reload
```

In a second terminal:

```powershell
cd frontend
npm run dev
```

Open the Vite address and **Sequence Design**. Validate/preview first, then run.
The latest successful request/result can be restored after refresh. Changed
inputs visibly mark saved results as snapshots; requests never rerun on load.

```powershell
$env:MPLBACKEND = 'Agg'
python -m pytest backend/sequence_design -q
python -m pytest backend -q
```

Export an actual example run, fitted circuit PNG/QASM/text, inputs and complete
results for a presentation (choose a new output directory on subsequent runs):

```powershell
python -m backend.sequence_design.experiment --output experiments/sequence_design_new_run
python -m backend.sequence_design.experiment --input experiments/sequence_design_verified/input.json --output experiments/sequence_design_replay
```

The saved `experiments/sequence_design_verified/` example proposed `GKGKGAGA`
from `GAGAGAGA`, with two changes and the required K. Its raw objective
0.03338474130049727 matched the exact reference (six tied optima), gap 0.
1398/2048 simulated shots were feasible; the ideal optimum probability was
0.5956668885353648. COBYLA converged in 29 evaluations. The exact higher-order
cost polynomial reconstructed all 16 states with maximum error about 1.67e-16.
These are recorded simulator results, not hardware or experimental chemistry.

The full existing backend suite passed 129 tests (one optional VQE module
skipped), followed by the focused suite passing 27 tests including the added
50-residue/eight-variable case: 256 states, 92 feasible under its constraints.

Tests cover input constraints, allowed-vs-required semantics, fixed positions,
one-based position decoding, hard-constraint infeasibility, direct scores, order
preference, all-state polynomial reconstruction and circuit probabilities for
quadratic and higher-order models, actual QAOA, exact gap, seeded replay,
no-feasible-sample behavior, QASM round trip, and actual molecular SVG output.

# Multi-choice sequence design

The website's **Multi-choice sequence design** execution method supports up to
two editable positions, each with 2–20 independently selected standard amino
acids. Other positions remain fixed. Use **Load 20-amino-acid example** for an
eight-residue template with two editable sites. Existing binary and large-circuit
modes remain available.

API endpoints: `POST /api/v1/sequence-design/multi/preview` and
`POST /api/v1/sequence-design/multi/optimize`. Requests use the existing sequence
request fields, with up to 20 unique entries in each position's `choices` array.
The ordinary `/preview` and `/optimize` endpoints retain their binary limits.

Each editable site uses `ceil(log2(number_of_choices))` qubits. Bits are assigned
in ascending position order; within a block the first qubit is least significant.
The decoded integer indexes that position's ordered choices. Twenty choices use
five qubits; two sites use ten qubits, 1,024 encoded states and 400 valid sequences.
The remaining 624 codes are invalid, never wrapped to an amino acid. They receive
energy `max(valid_raw_objectives) + lambda`, where `lambda = range(valid_raw_objectives)+1`.
Required residues and mutation budgets retain their existing dominating penalties.
The implementation verifies that every infeasible energy exceeds every feasible energy.

QAOA applies the complete diagonal cost and RX mixing. Parameter fitting applies
the diagonal phases directly to Qiskit statevector amplitudes to avoid repeatedly
synthesizing elementary gates; tests compare this evolution against the exported
circuit. The cost may have higher-order terms and is not assumed to be a QUBO.
The circuit remains downloadable as OpenQASM for IBM Composer. No hardware job is
submitted. Exact classical references, unconditional success probabilities and
infeasible shot counts include unused codes. Only feasible sequences actually
observed in the simulated shots are proposed. This small enumerated experiment
does not demonstrate quantum speedup.


For up to ten editable multi-choice sites without global enumeration and an explicit IBM Runtime workflow, see [Scalable QPU Lab](SCALABLE_QPU.md).
